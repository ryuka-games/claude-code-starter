## なぜqmdか

| 観点 | 自前実装 | qmd |
|---|---|---|
| 検索精度 | grepのキーワードマッチのみ | BM25+セマンティック+LLMリランキングの3層 |
| セットアップ | 自作が必要 | `npm install -g @tobilu/qmd` + フォルダ登録 |
| Claude Code連携 | 自作が必要 | プラグイン or MCPサーバーとして動く |
| メンテナンス | 自分で保守 | OSSコミュニティ（Shopify創業者Tobi製） |

## ツールロックインしない設計との両立

qmdは「マークダウンがフォルダにある」だけで動く。ファイル名、frontmatter、タグに制約を課さない。qmdを外してもファイルはそのまま使える。Obsidianに切り替えてもgrepに戻しても問題ない。

## qmdソースコード調査で見つかった/noteに活かせる知見

### 見出しスコアリングがチャンク分割を支配する

qmdは見出しレベルでブレークポイントにスコアをつける: h1=100, h2=90, h3=80, h4=70。空行=20、リストアイテム=5。見出しが低品質ブレイクに負けないようスコアを大きく離してある。

**→ /noteで見出しを丁寧に書くルールの裏付けがコードレベルで確認できた。** コードフェンス内は分割禁止。

### 非対称embeddingだからタイトルの質が重要

クエリとドキュメントで入力フォーマットが違う:
- クエリ: `task: search result | query: ...`
- ドキュメント: `title: ... | text: ...`

**→ タイトル（h1見出し）がembeddingの入力に直接使われる。** 「ナレッジ管理の仕組み」より「4フォルダ+追記デフォルトで設計した」のほうが検索でヒットしやすい。

### context機能で4フォルダの説明を検索に活かせる

フォルダに説明文をつけると、検索結果にcontextとして付与される。階層的プレフィックスマッチで全階層のcontextを連結。

qmd設定例:
```yaml
collections:
  research:
    path: docs/research
    context:
      "/": "AIや技術について調べた調査結果"
  decisions:
    path: docs/decisions
    context:
      "/": "設計判断とその理由の記録"
```

### intent機能で同じ単語の曖昧さを解消できる

`intent`パラメータはクエリ展開・リランキング・チャンク選択・スニペット抽出の4箇所に影響。例えば「design」で検索するとき、intent=「UIデザインパターン」とintent=「設計判断」で結果が変わる。

## 3層検索パイプラインの全体像

8ステップで動く:

| # | ステップ | やること |
|---|---|---|
| 1 | BM25プローブ | まずキーワード検索。高スコアならLLM展開をスキップ（コスト削減） |
| 2 | クエリ展開 | ローカルLLMでlex/vec/hyde変異を生成 |
| 3 | タイプ別ルーティング | lex→BM25、vec/hyde→ベクトル検索 |
| 4 | RRF融合 | 複数の検索結果をReciprocal Rank Fusionで統合 |
| 5 | チャンク選択 | 候補文書をチャンキングし最適チャンクを選択 |
| 6 | リランキング | Qwen3-Reranker-0.6Bでチャンク単位でリランク |
| 7 | スコアブレンディング | RRF上位は検索結果を信頼、下位はリランカーを信頼 |
| 8 | 重複排除+フィルタ | minScoreとlimitで最終結果を絞る |

**「書く側が楽で検索側が賢い」がqmdの本質。** タグに凝らなくても見出しさえ書けば意味で見つかる。

## 日本語対応の懸念（未検証）

| 層 | 懸念 |
|---|---|
| BM25 | SQLite FTS5のトークナイザがスペース区切り前提。日本語の形態素解析が入ってるか不明 |
| セマンティック | embeddinggemma（デフォルトモデル）の日本語精度が未確認 |
| チャンキング | 「1トークン≒4文字」は英語前提。日本語は1-2文字/トークンでチャンクサイズがズレる可能性 |

**→ 導入時にdocs/配下の日本語ファイルで検索テスト必須**

## MCPサーバーの構成

4ツールを公開:

| ツール | 用途 |
|---|---|
| query | メイン検索（lex/vec/hyde、intent、collection指定） |
| get | パスか#docidで単一文書取得 |
| multi_get | glob/リストで複数文書取得 |
| status | インデックスの健全性とコレクション一覧 |

サーバー起動時にコレクション情報を動的Instructionsとして注入。LLMがツールを呼ぶ前に「何が検索可能か」を知れる。

## 次のアクション

- qmdをインストールして4フォルダをcollectionとして登録
- contextをフォルダごとに設定（上記の例を参考に）
- **日本語ファイルで検索テスト**（BM25、セマンティック、両方）
- 検索精度を試して、足りなければfrontmatterやタグのルールを調整
- intent活用を/noteの検索ワークフローに組み込む検討
