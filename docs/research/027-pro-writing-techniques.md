# プロのライティング技法 — 70点から90点にするために

> **TL;DR**: 足りないのは4つ。書き出しのフック、セクション間のトランジション、冗長さの削除（初稿から20%削る）、まとめのバリエーション。日本語技術記事の名手に共通するのは「探索プロセスの可視化」。

## 書き出し: 5種類のフック

| フック | 例 |
|---|---|
| Problem-First | 「去年、TypeScript化で3日溶けた。原因はパスパラメータの型抽出」 |
| Question | 「カバレッジ87%でも本番でバグ。テストって何を信じればいい？」 |
| Scene-Setting | 「深夜2時。デプロイ直後にエラー率が跳ね上がった」 |
| BAB（Before-After-Bridge） | 苦しさ→解決後の世界→その方法 |
| 数字フック | 「3日間ハマった」「45%の確率で失敗」 |

## セクション間: エコーリンクとブリッジ文

- **エコーリンク**: 前のセクション末尾の言葉を次の冒頭で拾う
- **ブリッジ文**: 「ここまで◎◎。次は△△」の2要素
- **意味的トランジション**: 「設計の話はここまでだ。実装になると、また別の地雷が現れる」

## 冗長さ削除: 初稿から20%削る

| 冗長パターン | 修正 |
|---|---|
| することができます | できます |
| ～というものである | ～である |
| まず最初に | 最初に |
| 処理が行われた後に | 処理後に |

**Gernot Heiserの20-25%ルール**: どんな技術文章も初稿から20-25%削れる。1段落ごとに「この1文を削って意味が変わるか」を問う。

## まとめ: テーブル以外の5種類の締め方

| 締め方 | 効果 |
|---|---|
| Call to Action | 「次にこれを1つ試してほしい」 |
| Callback | 冒頭の問い・場面を締めで回収。記事が輪になる |
| Open Loop | 「次の問い」を残す。読者が考え続ける |
| One Key Takeaway | 一番伝えたいことを1文に圧縮 |
| Quote/Reframe | 他者の言葉で自分の主張を裏打ち |

## 名手のスタイル分析

3者に共通: **専門軸の明確さ、探索プロセスの可視化、現状分析+自分の予測**

- **uhyo**: 「この記事は何類型か」を冒頭で明示。AIとの最大の違いは「迷いながら考えている痕跡」
- **mizchi**: コードが先、説明が後。業界動向の「今後の予測」を必ず入れる
- **t_wada**: 大きな概念を3段階に分解して体系化。声入力で初稿を作り自然な語り口
